# 从 nanoGPT 学习 AI 模型训练

::: nanoGPT是一个2023年开源的复现GPT2规模LLM的项目，选择这个项目来讲AI是因为代码少而精髓，容易让人看懂。

本公众号的长期目的是，把一些ai或者其他技术相关的知识，用白话翻译，达到让一个五年级的小朋友也能听懂的程度。

## 大的方向概念

nanoGPT 是一个用很少代码实现的 GPT 训练项目。模型训练就跟小孩子学说话一样，本质上就是：准备一个字典，跟一本已经知道答案的组词题目，让模型根据前面的字猜下一个字，猜错了就再想想，重复很多次。

## 第一步：准备数据（给模型的故事书）

训练语言模型，先要有一大堆文本。小说、代码、网页、对话都可以，你希望模型怎么回复你，就要找类似的文本来训练，从教小朋友学说话的角度，就是要找合适的故事书来讲故事。

举个最简单的例子，假设你只教它：

```text
你好，小猪佩奇。你好，白雪公主。
```
那字典里只有"你好，小猪佩奇。白雪公主", 回答也只会从这些里面出来

如果你教它：
```text
你好，小猪佩奇。你好，白雪公主。你好，小白。你好，白雪。
```
字典的字符数没变，但是回答可能会更多样，","后面回答小的概率会更大，这是数据带来的对模型的直观影响。

但是机器看不懂字符，只懂0101010这种数字，所以它看故事书之前，我们要通过分词器，从字典（故事书）中把每个字的编号找到，然后把文字转成编号，机器就可以看懂了！

比如，"你好，小猪佩奇。白雪公主"为字典：

```text
你 -> 12
好 -> 35
， -> 4
```

这样，一篇文章就变成数字列表。计算机很擅长处理数字，不擅长直接处理文字。

### 训练集和验证集

数据一般要分成两份：

- 训练集：模型平时用来学习的题目。
- 验证集：不参与学习，只用来考试，看模型是不是只会背答案。

如果训练集成绩越来越好，验证集却没有变好，甚至变差，通常说明模型“背题”太厉害了。这叫过拟合，这种情况下是因为模型学习能力太强了，小数据轻松被记住了，变成了背题的效果，一般加数据（给它讲更多故事）、减少模型容量（一次不给它太多时间去思考和记住故事），可以防止它"背题"。

## 第二步：每次取一小段文字

全部文本可能很大，不能每次都塞进模型。nanoGPT 会随机拿几段固定长度的文本，这一批数据叫 batch, 有多少批叫 batch_size。

例如原文是：

```text
春眠不觉晓，处处闻啼鸟。
```

可以截出：

```text
输入：春眠不觉晓
目标：眠不觉晓，
```

你会发现，目标就是输入整体往后挪一个位置。模型看到“春”，猜“眠”；看到“春眠”，猜“不”；以此类推。

这就是语言模型训练数据最核心的构造方式：用前面的内容预测后面的内容。

## 第三步：让模型理解数字之间的关系

token 编号本身没有大小意义。例如 12 不比 35 “更大”。所以模型先会查一张表，把每个编号变成一组浮点数，这一步叫 embedding（词向量）。

除了“这是什么 token”，模型还要知道“它在第几个位置”。“我打你”和“你打我”用的是相同的字，顺序不同，意思就不同。因此 nanoGPT 还会加上位置编码。

简单说，送进模型的每个 token 都带着两类信息：

- 这个 token 是谁。
- 它在这句话的什么位置。

## 第四步：注意力机制在看什么

Transformer 最有名的部分叫自注意力（self-attention）。大白话说，就是每个字在决定自己该怎么理解时，会回头看前面哪些字更重要。

例如：

```text
小明把书放到桌子上，因为它很重。
```

读到“它”时，模型会重点参考前面的“书”，而不是“小明”或“桌子”。注意力机制就是用一套可学习的计算方式，决定该多看谁、少看谁。

语言模型有一条规矩：不能偷看未来。预测第 5 个 token 时，只能看前 4 个 token，不能先看到标准答案。nanoGPT 通过一个下三角的 mask 把未来位置遮住。

## 第五步：算一算错得有多离谱

模型会为“下一个 token 是什么”给出一张概率表：

```text
好：60%
热：25%
冷：10%
其他：5%
```

正确答案如果是“好”，这次表现不错；如果正确答案是“冷”，那就错得比较多。这个“错多少”的分数叫 loss（损失）。

训练的目标不是让某一题全对，而是让整批数据的平均损失越来越低。训练日志里最值得先看的数字就是 loss。

## 第六步：模型怎么从错误里学习

知道错了还不够，关键是怎么改。训练通常按下面的顺序进行：

1. 前向计算：把输入送进模型，得到预测和 loss。
2. 反向传播：计算每个参数对错误要负多大责任。
3. 优化器更新：按这个责任微调参数。
4. 清空旧梯度：准备下一轮训练。

可以把参数理解成无数个小旋钮。反向传播会告诉每个旋钮该往哪个方向转一点，优化器负责真的去转。一次只改一点点，但重复几百万次，模型就能学到复杂的规律。

学习率（learning rate）决定每次转多少：太大容易转过头，训练发散；太小则进步很慢。nanoGPT 常用学习率预热和余弦衰减，让训练开始时更稳，后期更细地调整。

## 第七步：为什么需要 GPU 和混合精度

模型训练本质上是大量矩阵乘法。GPU 能同时做很多相同类型的计算，因此比 CPU 更适合这项工作。

混合精度则是在不明显影响结果的前提下，用更短的数字格式做部分计算。好处是更快、占用显存更少。代价是数值可能不稳定，所以训练代码通常还会做梯度缩放等保护。

如果显存不够，常见办法有：

- 减小 batch size：一次少喂几段文本。
- 减小 block size：每段文本短一些。
- 减小模型层数、隐藏维度或注意力头数。
- 使用梯度累积：分几次计算，再合起来更新一次参数。

## 第八步：训练好后如何生成文字

训练完成后，给模型一段开头，它就能一个 token 一个 token 地往后写。

模型并不是每次只取概率最高的答案。那样写出来常常很死板。实际生成会用 temperature、top-k 或 top-p 做采样：

- temperature 越低，输出越保守、稳定。
- temperature 越高，输出越随机，也更容易跑题。
- top-k 只从概率最高的 k 个候选里挑。
- top-p 只从累计概率达到某个范围的候选里挑。

所以“模型回答不同”不一定代表它坏了，很多时候是采样本来就带有随机性。

## 看 nanoGPT 代码时抓住这几块

第一次看源码，不需要逐行硬啃。先按职责分成下面几块：

| 模块 | 它做什么 |
| --- | --- |
| 数据加载 | 从文本中随机取输入和目标 |
| GPT 模型 | embedding、注意力层、前馈网络、输出层 |
| 训练循环 | 前向计算、反向传播、优化器更新 |
| 配置 | 模型大小、学习率、批大小、训练轮数 |
| 采样脚本 | 加载模型，根据提示词生成文本 |

看懂这条主线就够了：**数据进来 -> 模型预测 -> 计算 loss -> 更新参数 -> 定期验证和保存模型**。

## 常见误区

### loss 下降了，模型就一定好？

不一定，训练集 loss 下降只代表它越来越会做练习题。还要看验证集 loss、实际生成内容，以及任务本身的评价指标。

### 参数越多越好吗？

也不一定。参数更多意味着对数据、显存要求更大、训练时间更长。数据量不够时，大模型可能训练完变成会背题。

### 训练一次就能聊天吗？

预训练模型学到的是“接着写”的能力，不天然懂得按人类指令办事。想让它更像聊天助手，还要做指令微调、偏好对齐和安全处理等后续工作。

### 只要有代码就能复现结果吗？

不能。随机种子、数据清洗方式、硬件、训练时长、超参数都会影响结果。复现时要同时记录代码版本、数据版本和配置。

## 一条实用的学习路线

1. 先用小文本跑通 nanoGPT，确认数据读取、训练和生成三个环节都能工作。
2. 把模型缩小到单张显卡能跑的程度，观察 loss 是否下降。
3. 改一个参数再跑一次，例如 batch size 或学习率，比较训练曲线。
4. 读 `model.py`，重点理解 token embedding、注意力 mask 和 `forward` 的输入输出。
5. 最后再看分布式训练、编译加速和大规模数据处理等工程细节。

不要一开始就追求训练大模型。先把一个小模型从数据到输出跑明白，后面的概念都会更容易落地。
