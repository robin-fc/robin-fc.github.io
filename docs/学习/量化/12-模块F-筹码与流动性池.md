# 模块 F：筹码与流动性池（筹码分布 / 订单簿 / 大户）

> 对应 01 总纲 模块 F 的 **F1~F3**。从「价/量/指标」走到「谁的钱、在哪个价位」——筹码与流动性是加密市场特有的富矿。

![筹码分布（成本分布）](/assets/quant/a19.svg)

## F1 筹码分布（成本分布 / Volume by Price）

- **定义**：把历史成交按「价格」聚合（而非按时间），得到「每个价位的累计成交量」，即套牢盘/获利盘分布。
- **计算口径**：`VBP(价) = Σ 该价位的成交量`（可按时间衰减权重）；筹码峰 = 峰值区。
- **常见用法**：价在筹码峰下方 = 大量套牢盘抛压；突破密集区后回踩不破 = 支撑强；筹码越集中越健康。
- **坑与误区**：筹码分布要**跨所有交易所**才全（单所严重偏）；衰减权重的半衰期是主观参数；插针会造出假密集区。
- **最小验证（BTC）**：1d，统计「价从下往上突破 30 日筹码峰」后 N 根 vs「在峰下反弹」，看突破峰后的持续性。

## F2 订单簿 / 流动性池（Order Book）

- **定义**：订单簿是「所有挂单」的实时快照；流动性池 = 某价位区间的挂单深度。
- **计算口径**：买/卖挂单量、价差（best bid/ask）、深度（前 N 档累计）、订单流比（主动买/卖）。
- **常见用法**：大挂单 = 潜在支撑/阻力（但可撤单）；订单流（taker 方向）判断真实买卖压力；「撤单」识别假单。
- **坑与误区**：挂单可秒撤（spoofing 假单）；单所订单簿不代表全网；高频撤单使「大挂单」信号噪声大。
- **最小验证（BTC）**：用「订单流比（主动买/卖）」做短线信号，统计后 N 分钟方向命中率；对照「价差」单独，看订单流是否更强。

## F3 大户 / 链上 / 资金流

- **定义**：通过「大户地址/交易所净流入、链上转账、资金流（USD in/out）」识别「聪明钱」动向。
- **计算口径**：交易所净流入 > 0 = 币进交易所（偏卖压）；大户地址异动；资金费率与 OI（模块 F 下篇）。
- **常见用法**：大量币进交易所 = 潜在抛压；大户持续净流入 + 价稳 = 吸筹嫌疑。
- **坑与误区**：地址归属是「估计」不是确定（同一地址可能多个主体）；链上数据有滞后；「聪明钱」标签自我实现/噪声。
- **最小验证（BTC）**：把「交易所净流入/流出」当领先指标，统计其与后 N 日收益的相关性；对照「随机基线」。

## 本篇小结

| 知识点 | 核心读盘点 | 失效场景 |
| --- | --- | --- |
| F1 筹码分布 | 跨所 VBP，看密集峰 | 单所偏、插针造假峰 |
| F2 订单簿 | 订单流比 > 价差 | 假单撤单 |
| F3 大户/链上 | 净流入=抛压估计 | 地址估计、滞后 |

> 筹码/流动性把「价量」升级为「结构」：先看「钱在哪、谁在动」，再谈方向。下一篇补加密特有的衍生品结构。
